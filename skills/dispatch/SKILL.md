# 把任务派给远程 worker

worker 是另一台机器上、用另一个账号登录的 Claude Code 后台会话。它和内置 Sub Agent 的区别决定了用法：

- 它看不到本会话的上下文、文件和工具结果。
- 它在自己的代码副本上工作，和本机只通过 Git 远端同步。
- 它消耗的是 worker 账号的额度，不是本账号的。
- 它和你之间可以随时互发消息。

## 什么时候派发

只在用户明确要求时派发。适合派发的是能独立完成、验收标准明确的任务。需要频繁查看本机文件或依赖本会话大量上下文的任务不适合。

## 派发前：代码要已经在远端

`worker_dispatch` 会读取本会话所在项目的仓库地址、分支和当前提交，在 worker 上克隆或更新这个项目，并为这次任务建一个独立的 worktree。worker 只能拿到远端有的内容，所以：

- 有未推送的提交或未提交的改动时，工具会拒绝并说明差了什么。先提交、推送，再派发。
- 提交和推送是对外的动作：用户没有授权过的话，先问用户。
- 任务确实不需要那些未提交的改动时，可以加 `allow_unsynced=true`。

工具还会检查 worker 的额度，低于门槛会拒绝。被拒绝时把额度情况告诉用户，由用户决定是否用 `force=true`。

要派发别的项目，用 `project_dir` 指定它在本机的路径。与代码无关的任务，用 `cwd` 指定 worker 上一个已信任的目录。

## 任务说明怎么写

仓库、分支、提交和同步规则由工具自动写进任务开头，不用重复。`task` 里写清楚：

1. **目标**：要改什么、为什么改，相关文件或模块的位置。
2. **边界**：不要碰什么。
3. **验收标准**：怎样算完成，要跑哪些测试。
4. **交付分支**：默认推回本机当前所在的分支；想让它推到别的分支就在这里写明。

不要写“像刚才讨论的那样”“上面那个文件”这类指代本会话的话。

## 派发之后

- **不要等，也不要轮询**。工具立刻返回；代码准备好、会话启动后会收到一条 `[agent-remote-worker]` 通知，准备失败也会通知。之后 worker 的进度、提问、完成汇报同样会自动出现，本会话空闲时会被唤醒。
- **想看进度**用 `worker_status`，准备中的任务会显示当前步骤和已用时间。
- **追加要求**用 `worker_send`。worker 正忙时会在当前工具调用结束后读到，不会打断正在运行的命令。
- **要立刻停下**用 `worker_stop`，之后可以用 `worker_resume` 续跑。
- 把 worker 的重要汇报转述给用户，不要只说“worker 完成了”。

## 回答 worker 的提问

worker 提问后会停下等你。按问题的性质处理：

- **你能定的**：任务范围内的技术选择、用户已经表过态的事。直接用 `worker_send` 回复。
- **要问用户的**：需求取舍、有风险或不可逆的操作、超出原任务范围的事。先问用户，拿到答复再转给 worker。

worker 汇报某个操作被权限设置拒绝时，由你判断：能换一种不需要该权限的做法，就告诉它怎么换；确实需要放开权限，就告诉用户是哪个操作、为什么需要，用户同意后用 `worker_stop` 和带 `permission_mode` 的 `worker_resume` 续跑。不要替 worker 在本机执行那个被拒绝的操作。

## 审查和收尾

worker 汇报完成后：

1. 在本机 `git pull`（或 fetch 它给的分支）。
2. 看 diff，按验收标准检查，必要时在本机跑测试。
3. 有问题用 `worker_send` 让它修，说清楚哪里不对、期望是什么。
4. 向用户汇报：做了什么、你检查了什么、还有什么没验证。
5. 确认不再需要后用 `worker_remove` 删除会话并清理它的工作目录。目录里还有没推送的内容时它会拒绝，这时先让 worker 推送。

## 出问题时

- **工具说 workRoot 未被信任**：告诉用户两种办法，由用户选：在 worker 上进入节点配置的 `workRoot` 运行一次 `claude` 并接受信任提示；或在 `~/.claude/workers.json` 里给该节点加 `"trustWorkRoot": true`，让插件自动信任。不要自己去改这个配置。
- **会话状态是“卡在权限确认”**：告诉用户，可以用 `worker_stop` 后以别的 `permission_mode` 执行 `worker_resume`。
- **长时间没有消息**：用 `worker_status` 看状态，再用 `worker_send` 问进度。
